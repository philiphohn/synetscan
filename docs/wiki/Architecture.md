# Architecture and DSM Integration

SynetScan consists of a background service written in Python (standard library only), a small CGI program that guards the service, and a web interface in plain HTML, CSS and JavaScript with no build step.

## Overview

```
DSM window (iframe)  index.html · js/app.js · css/dsm.css
      │  fetch api.cgi?action=…   (DSM session cookie + SynoToken)
      ▼
api.cgi  ─ validates the session via DSM's authenticate.cgi, checks admin group
      │  JSON over unix socket  /var/packages/SynetScan/var/synetscan.sock
      ▼
synetscand  (package service, runs as the unprivileged package user)
  ├─ scheduler (periodic scans, scan on start)
  ├─ scanner   discovery → enrichment → classification
  └─ store     devices.json · events.json · scans.json · config.json
```

## Repository layout

```
src/
  bin/synetscand          daemon launcher (finds python3)
  lib/synetscan/          Python package (stdlib only, Python ≥ 3.6 / tested 3.8 + 3.12)
    scanner.py probes.py netinfo.py dnsmsg.py classify.py targets.py ipv6.py
    store.py config.py daemon.py cgi_main.py oui.py util.py
  share/oui.txt.gz        MAC vendor database (generated by tools/build_oui.py)
  ui/                     DSM web UI (config, synetscan.js, index.html, api.cgi, css, js, images)
spk/                      INFO template, conf/privilege, lifecycle scripts, package icons
tools/                    dev server, mock DSM desktop, screenshot and demo tools, build helpers
tests/                    unit and security tests
build.sh                  builds dist/SynetScan-<version>-noarch.spk
```

## Python modules

| Module | Responsibility |
| --- | --- |
| `daemon.py` | The service: owns all state, runs the scheduler and the scan thread, serves the JSON API on a Unix socket (`api_*` methods) |
| `scanner.py` | One scan: target list, multicast discovery, sweep, ARP table, enrichment, ARP verification, NAS merge, IPv6 merge, classification |
| `probes.py` | Unprivileged probes: TCP connect scan, UDP poke, system ping, reverse DNS, NetBIOS, mDNS browse and direct queries, SSDP, WS-Discovery, a minimal HTTP client (titles, UPnP descriptions), Wake-on-LAN |
| `ipv6.py` | IPv6 discovery: own addresses, candidate interfaces, multicast queries, all-nodes echo, EUI-64 pokes, neighbour table via netlink or `ip -6 neigh`, address sorting and prefix filtering |
| `netinfo.py` | The NAS's interfaces, gateways, DNS servers, ARP table, and the local/remote check for the browser (`client_location`) |
| `targets.py` | Parses ranges and builds the target list (`clamp_network` for large networks) |
| `classify.py` | Device types, port names, default ports, display-name selection and junk-name filters |
| `store.py` | Device list, events, scan history, config: merging scan results, offline logic, retention, CSV export |
| `config.py` | Defaults and validation of every setting |
| `dnsmsg.py` | DNS message encoding and parsing for mDNS |
| `oui.py` | MAC vendor lookup (longest prefix match in `share/oui.txt.gz`) |
| `cgi_main.py` | `api.cgi`: request checks, DSM authentication, admin check, forwarding to the service |
| `util.py` | Text cleaning, atomic JSON writes, logging, MAC helpers |

## Package lifecycle

`spk/INFO.in` declares the package: `arch="noarch"`, `os_min_ver="7.0-40000"`, `dsmuidir="ui"`, `dsmappname="SYNO.SDS.SynetScan.Instance"`, `thirdparty="yes"`, `silent_upgrade="yes"`, `startable="yes"`, `ctl_stop="yes"`. `spk/conf/privilege` sets `run-as: package`.

| Script | Does |
| --- | --- |
| `preinst` | Finds Python 3 (Python 3.9 package, `/usr/local/bin`, `/usr/bin`, `/bin`) and requires ≥ 3.6; otherwise aborts with a message Package Center shows |
| `postinst` | Creates the data folder, makes `api.cgi` and `synetscand` executable |
| `start-stop-status` | `start`: launches `synetscand` in the background (umask 077), writes the PID file, waits up to 10 s for the socket. `stop`: SIGTERM, up to 15 s, then SIGKILL. `status`: exit 0 if running, 3 otherwise. `log`: prints the log path. |
| `preuninst`, `postuninst`, `preupgrade`, `postupgrade` | Nothing |

## The service

- `synetscand` (shell) finds Python and starts `synetscan.daemon.run(var_dir)` with `-I` (isolated mode), with the log file as argument.
- On start it sets umask 077, tightens the modes of existing data files, raises the open-file limit (to 4096 if allowed), loads the store, and listens on `synetscan.sock` (mode 0600). The socket is bound relative to the data folder, so long paths don't hit the 108-byte limit of Unix socket paths.
- **Scheduler thread**: starts a scan on service start if `scan_on_start`, then checks every 5 seconds whether the next scan is due (`last scan end or last attempt + interval`).
- **Scan thread**: at most one scan at a time. Progress (phase, done, total, found) is exposed through `status`. A cancel event stops it between steps.
- **API**: one request per connection, one line of JSON in, one line out, a 30-second idle timeout, 1 MB maximum request. Handled in threads.
- **Store**: a single lock. Each change rewrites the affected file atomically (`tempfile` + `os.replace`, mode 0600).

## DSM integration

- **Window.** Since DSM 7.2, a `"type": "legacy"` app entry opens in a browser tab, where the page can't use the DSM session. So `ui/config` registers an ExtJS application, `SYNO.SDS.SynetScan.Instance` (see `ui/synetscan.js`), whose `SYNO.SDS.AppWindow` holds `index.html` in an iframe. `dsmappname` in INFO names the same class, which is what Package Center's **Open** button uses. `allUsers: false` limits the menu entry to administrators.
- **Focus.** Clicks inside an iframe never reach DSM. The page posts a message on mousedown, and the window brings itself to the front and closes DSM's open menus.
- **Session token.** The UI reads the SynoToken from the DSM desktop (its parent window). It also receives it in the URL fragment, which no server or log ever sees, and removes it from the address bar right away. API calls send it only as the `X-SYNO-TOKEN` header, CSV export included.
- **Language and fonts.** The UI reads DSM's session language (`ger` means German) and DSM's font from the parent window.
- **Opened outside DSM.** If `index.html` is opened in a tab on its own, the page offers **Open in DSM**, which goes to `/?launchApp=SYNO.SDS.SynetScan.Instance`.
- **Service socket.** The socket has mode `0600`. Only the package user, which DSM also runs the package CGI as, can reach the service. Everyone else has to go through `api.cgi` and its DSM session and admin checks.
- **Local or remote.** `api.cgi?action=client` compares the browser's address (`REMOTE_ADDR`) with the networks of the NAS's connected physical interfaces. See [Local Access](Local-Access-QuickConnect-VPN-and-DDNS).
- **Errors.** The CGI always answers HTTP 200 with `"success": false`, so DSM's nginx never swaps the answer for an HTML error page. The UI translates errors by their `code`.
- **Time zone.** The service reports the NAS's UTC offset, and the UI shows all times in the NAS's time zone, like DSM.

## The request path in `api.cgi`

1. Read the request body completely first. A web server may drop the answer of a CGI that exits with its body unread.
2. Refuse requests the browser marks as cross-site (`Sec-Fetch-Site` other than `same-origin` or `none`) → `cross_site`. *Since 1.1.5.*
3. Ask DSM's `authenticate.cgi` (session cookie + token from the header) → `auth`.
4. Check membership of `administrators` (`/etc/group`, then `synogroup`) → `permission`.
5. Allow only known actions → `unknown_action`.
6. Allow GET for read actions only. Everything else needs POST → `method`.
7. POST needs `Content-Type: application/json` → `bad_request`. *Since 1.1.5.*
8. Answer `client` directly. Forward everything else to the service with the user name, and relay its answer. The CSV export becomes a file download.

## Web interface

- `index.html` loads `js/i18n.js` (translations), `js/icons.js` (inline SVG icons and type colours) and `js/app.js` (the whole app), all with a `?v=<version>` suffix for cache busting.
- A Content Security Policy allows only the page's own scripts and connections. *Since 1.1.5.*
- `app.js` is plain JavaScript without a framework or build step. It renders the four pages, polls `status` (10 s, 1.5 s while scanning), and keeps the sort order and last page in `localStorage`.
- All text from the network is inserted as escaped text.
